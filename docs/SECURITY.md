# Security

## Permissions

The extension asks for the least it can, when it needs it. It never asks for `<all_urls>`, `tabs`, `history`, `cookies`, `webRequest`, `scripting` or content scripts.

**In the current build:**

| Permission                                                                 | Purpose                                        | Why it's needed                                                                                                                                                           | What eGuard does with it                                                                                  | What eGuard does not do                                       |
| -------------------------------------------------------------------------- | ---------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------- |
| `storage`                                                                  | Keep the connection, policy and last sync time | Survive browser restarts; hold the access token in memory-only `storage.session`                                                                                          | Stores the installation credential, the signed family policy and sync/health timestamps                   | Store pages visited, form data or anything typed              |
| `alarms`                                                                   | Periodic sync and rule checks                  | MV3 workers stop when idle; alarms wake them (policy every 5 minutes, rules every minute for focus hours and approvals that end)                                          | Downloads the latest policy, re-applies and re-verifies the blocking rules                                | Run anything else in the background                           |
| `declarativeNetRequest`                                                    | Block sites                                    | The browser matches the rules itself, so eGuard's code never sees the pages visited                                                                                       | Installs block/allow rules compiled from the verified policy, and reads them back to check they're intact | Inspect, modify or record page content                        |
| `webNavigation`                                                            | Show the eGuard block page                     | A plain block rule shows the browser's own error; a redirect rule would need access to all sites. Only `onErrorOccurred` is used, so only failed top-level loads are seen | Re-checks a failed load against the policy and, if eGuard blocked it, swaps in the block page             | Store, count or send the addresses of pages that fail or load |
| `privacy` (Chrome build only)                                              | Keep Chrome's Safe Browsing on                 | The only way to read and hold `privacy.services.safeBrowsingEnabled`; Edge ignores it and Firefox has no such setting, so their builds don't ask                          | Holds Safe Browsing on while the family's policy asks for it; hands it back when not, or on disconnect    | Read or change any other privacy setting                      |
| Host: the eGuard API origin                                                | Talk to eGuard                                 | Lets the worker call the API without opening CORS on the server                                                                                                           | Pairing, token refresh, policy download, access requests, health reports, daily counts                    | Contact any other service                                     |
| Hosts: `*.google.com`, `*.google.com.ph`, `*.bing.com`, `*.duckduckgo.com` | SafeSearch                                     | Redirect rules that add `safe=active` / `adlt=strict` / `kp=1` need host access to those sites                                                                            | Rewrites search URLs on those engines to their SafeSearch setting                                         | Read search queries or results                                |

`tabs.create`/`tabs.update` (onboarding, dashboard, block page), `action` (badge), `extension.isAllowedIncognitoAccess()` and `management.getSelf()` (force-install check) need no permission.

Install warnings this produces in Chrome: "Block content on any page", "Read your browsing history" (Chrome's wording for `webNavigation`; eGuard keeps no history), and "Read and change your data on" the search sites, and on Chrome "Change your privacy-related settings" (`privacy`). The store listing explains each. Adding `privacy` to an installed Chrome build disables it until the user accepts the new warning, so it must ship before the first public release or with a planned re-consent.

Every addition must update this table, the manifest test in `apps/extension/src/config/config.test.ts`, and the store listing's permission justifications.

## Threat model

| Threat                                                     | Mitigation                                                                                                                                                                                                                                                           | Residual risk (stated to parents)                                       |
| ---------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Web page messages the extension                            | No `externally_connectable`, no content scripts; the router refuses any sender that isn't one of this extension's own pages (checked by id and URL prefix), then parses with strict zod schemas                                                                      | none known                                                              |
| XSS in extension pages                                     | React escaping; lint bans `dangerouslySetInnerHTML`/`innerHTML`, `eval`, `new Function`; CSP `script-src 'self'; object-src 'none'; base-uri 'none'; frame-ancestors 'none'; connect-src 'self' <api>`                                                               | none known                                                              |
| Network attacker                                           | HTTPS enforced for production builds at build time; `redirect: "error"`; `credentials: "omit"`                                                                                                                                                                       | none known                                                              |
| Stolen refresh token                                       | Rotation on every use + reuse detection revokes the installation (server, Phase 2)                                                                                                                                                                                   | window until next legitimate refresh                                    |
| Child re-pairs the browser to another account              | Already-paired browsers refuse new codes; removal only from the parent dashboard                                                                                                                                                                                     | a child who can remove the extension can reinstall it fresh (see below) |
| Child edits extension storage or rules via developer tools | Every stored value is schema-checked on read; policies are signed by eGuard and re-verified on every read, so an edited one is discarded; installed rules are read back on every status check (shown as "Website protection not active") and re-applied every minute | developer mode can be blocked by policy (`DeveloperToolsAvailability`)  |
| Child forges "Continue" or "allowed" from the block page   | The block page only sends a URL; the worker re-evaluates it against the verified policy and refuses Continue for anything but a "Warn first" site, and access only changes when the parent's signed policy does                                                      | none known                                                              |
| Private windows                                            | Rules only apply where the extension runs; eGuard checks `isAllowedIncognitoAccess()` and won't report Protected until it's allowed, with per-browser steps                                                                                                          | parent must allow it once per browser                                   |
| Child disables or removes the extension                    | Not preventable by any extension. Force-install by enterprise policy makes it impossible (Guided); otherwise the backend notices the silence and alerts the parent within 24 h                                                                                       | stated in the capability matrix                                         |
| Private windows                                            | Extension checks `isAllowedIncognitoAccess()` and guides the parent to allow it (Phase 5)                                                                                                                                                                            | parent must act once per browser                                        |
| Another browser / profile / device                         | Out of scope for a browser extension; eGuard says so                                                                                                                                                                                                                 | stated                                                                  |
| Rollback to an older, looser policy                        | Version must increase; lower versions are refused and logged                                                                                                                                                                                                         | none known                                                              |
| Internal errors leak details                               | Errors shown to people are fixed, friendly strings; 5xx server text is never shown; diagnostics are kept in memory, separate from UI, without URLs or tokens                                                                                                         | none known                                                              |

## Practices

- TypeScript `strict` + `noUncheckedIndexedAccess`; typescript-eslint `strictTypeChecked`.
- All external input (messages, API responses, stored state) is parsed with zod; no `as` casts on untrusted data.
- `npm audit` runs clean; dependencies are few (React, Zustand, Zod, lucide, fonts). Review before adding any.
- No secrets in the client: the extension holds only its own installation credential. API keys for any third-party service stay on the server.
